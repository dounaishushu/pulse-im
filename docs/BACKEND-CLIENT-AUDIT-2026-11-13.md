## 已修复的缺陷

| 级别 | 范围 | 原问题 | 修复及验证 |
| --- | --- | --- | --- |
| P1 | 消息与媒体缓存 | Web/PC 的置顶等消息读取等待媒体授权时，成员版本可能已被另一个请求推进，迟到结果仍可回填旧消息 | 共用消息处理再次检查捕获的成员版本；Android/iOS 同步补充保护。Node 确定性并发回归验证旧置顶媒体响应被拒绝，保留原先历史页保护 |
| P2 | F050 定时禁言 | PHP 支持 -1、0、1–43200 分钟，Go 和适配器只支持永久/解除，Web 原有定时选项请求失败 | Go 接受分钟时长，兼容已安装客户端的布尔协议；三套适配器改传分钟；手机和 PC 恢复时长入口。回归覆盖范围校验、到期、永久覆盖、解除、普通成员越权和混合参数拒绝 |
| P2 | F026 隐藏会话 | 隐藏后收到新消息仍不在会话列表出现，与旧 PHP 不同 | 新消息事务恢复处于隐藏状态的有效成员；保持历史清空、删除与已读不变；幂等重放不会重新打开后来隐藏的会话。增加部分索引，常规群发送无需扫描全部成员的普通状态 |
| P2 | F021/F034 @ 提醒 | 服务端保存了提及，但会话列表没有数量和定位序号，客户端刷新后丢失“有人 @ 你”提示 | 按当前可见会话页汇总，包含免打扰群；四端接收数量和序号。回归覆盖本人排除、@所有人、仅送达仍提醒、已读、个人删除、清空、编辑移除提醒；计数上限 999，另返回截断标志 |
| P2 | F035 消息定位 | Go 的 before_seq 包含上界；三套适配器又额外拼入目标消息，产生重复，引用消息还可能令批量上下文校验失败 | 上界改为目标序号减一，首条消息不查询旧页，前段恢复升序。覆盖首条、第二条及中间消息，真实客户端检查定位结果不重复 |
| P2 | PC 独立记录窗口 | 下一页把上一页最小序号作为包含式上界，随后被自身严格边界检查拒绝 | 传递上一页最小序号减一；通过实际窗口管理器的 IPC 处理器与 Go 适配器验证 60 条消息跨两页无重无漏。窗口环境使用桩，本轮没有重新启动 Electron UI |
| P2 | F035 全局搜索 | 用随机 UUID 排序并翻页，结果不保证按消息时间排列 | 使用 created_at、id 复合排序和游标，旧 before_id 字段保持兼容；读取游标时校验当前可见性。回归验证 UUID 与时间逆序、相同时间戳、不可见和不存在游标 |
| P2 | 后台用户详情 | 详情和编辑前读取依赖缓存或前 100 个用户，老用户可能显示不存在，缓存版本也可能陈旧 | 增加受 users.view 权限约束的按 ID 读取接口，编辑前重新读取当前版本；不返回 password_hash。验证普通用户、无模块权限管理员及不存在用户被拒绝 |
| P2 | 登录错误反馈 | 两步验证要求和设备数上限落入泛化提示；Web/PC 登录表单依赖“两步验证”文字显示额外输入框 | 四端补充明确文案，保留 error code；Web/PC 补齐 /auth/security 映射。同设备替换和第九台设备拒绝有独立后端回归。用户实际报告的 409 未取得响应体，不能将其原因定为设备上限 |
