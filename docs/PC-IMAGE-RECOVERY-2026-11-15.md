# PC 2.4.159：群聊坏图与图片加载恢复

日期：2026-11-15（北京时间）。源码标签：`pc-v2.4.159`。本版配套 Android 验收包为 `0.2.87 (89)`，见 [安卓相册修复](ANDROID-PICKER-FIX-2026-11-15.md)。

## 原作者反馈与实际证据

原作者确认使用 PC `2.4.158`，拖入图片、按回车发送后，群聊出现 `image.jpg` 坏图。

服务器中定位到 20:24:23–20:24:26 的十条对应图片消息。十份原图及十份预览文件全部存在，原图均为 106,272 bytes，预览均为 36,623 bytes；JPEG 头尾有效，十份原图内容 SHA-256 相同。使用同一图片内容，在独立测试群、实际安装的 2.4.158 中重放拖入十张图片并按回车，普通网络下十张均能显示。

进一步对接收图片制造一次受控加载失败，恢复网络后，2.4.158 仍留下十张坏图。该版本的主聊天图片缺少失败后的重新授权、重试和明确重试入口；授权链接有效期两分钟，延迟加载或临时请求失败也可能进入同一无法恢复的状态。截图当时没有完整网络记录，不能把人为注入的故障认定为当时唯一触发原因。

## 修复行为

- 图片加载失败时，按有限次数重新获取当前登录的媒体授权，再通过原有账号缓存通道加载。正常成功的图片不增加请求。
- 自动尝试最多三次，采用 400 ms、1,800 ms、6,000 ms 的间隔。持续失败后显示“图片加载失败，点击重试”，使用原图片按钮重试，隐藏浏览器坏图图标。
- 重新校验当前账号、令牌、会话、消息版本、历史打开轮次及锁定状态。迟到的授权响应不能写回已切换的页面；401 / 403 / 404 / 409 不无限重试。
- 授权刷新支持强制更新，仍合并同一媒体的并发授权请求。未放宽媒体权限、登录撤销或群成员校验。

## 验收与边界

本版通过 Windows x64 NSIS 实际安装，读取安装目录内 `app.asar`，3,124 个源码资源与当前 PC 源码逐字节一致，版本及生产 HTTPS / WSS 配置一致。

验收使用两个专用测试账号及仅含这两个账号的测试群，连接现有正式 HTTPS / WSS 服务；没有向反馈截图所在的用户群发送测试消息。使用反馈图片的相同字节，但不会把该图片、原始访问令牌或原始用户日志发布到 GitHub。

| 检查 | 结果 |
| --- | --- |
| 客户端契约与恢复测试 | Node 46 项通过，0 跳过；覆盖重试上限、手动重试、账号/会话切换、锁定、权限拒绝和并发授权合并 |
| 实际安装端拖入十张图片，按键盘回车发送 | 接收端十条独立发送编号，十张实际解码显示 |
| 真实失效授权链接 | 原缓存通道返回 403；重新授权后返回 200，图片重新解码显示 |
| 持续阻断至重试耗尽 | 明确显示重试入口，隐藏坏图；恢复网络后点击重试成功 |
| 一组十张失败图片 | 自动恢复及手动补试后十张全部可显示，均经过原账号的保护通道 |
| 包内资源和生产地址 | 3,124 项一致，0 差异；API `/api/v2`，WebSocket `/api/v2/realtime` |

“受控阻断”使用测试窗口的 Chromium 调试接口，仅影响该接收测试窗口的图片加载。自动重试有上限，长时间无法访问时仍需要用户主动重试；没有用反复刷新或无限轮询掩盖权限错误。没有将两个测试账号的验收称为 221 人同时在线的负载验收。

Go 服务及其部署文件本轮不需要更换，现有媒体授权接口已支持本次修复。测试结束后恢复专用测试账号原停用状态、撤销其测试会话，停用本轮仅含专用账号的测试群；正常用户和会话不变。

## 打包与交付

Windows 包仍未配置 Authenticode 发布者证书。Android `0.2.87` 仍为与前包相同证书的调试签名验收包；原正式 keystore 与 Firebase 配置仍需作者补齐。详见 [打包交接说明](CLIENT-PACKAGING-HANDOFF-2026-11-15.md)。

```powershell
cd pc
$env:PULSE_API_URL = 'https://api.imapi.shop/api/v2'
$env:PULSE_WS_URL = 'wss://api.imapi.shop/api/v2/realtime'
npm ci
npm run check
npm run dist -- --publish never --config.electronDist=D:/IM/pc/node_modules/electron/dist
```

最后一个路径应按作者自己的仓库位置调整，使用锁定版本的本地 Electron。源码回归在根目录运行 `node --test client-tests/*.test.cjs` 及 `python scripts/sync-browser-core.py --check`。

Release 提供 EXE、配套 APK、SHA256SUMS、安装资源核对及脱敏验收日志。原始反馈图片和生产原始诊断留在本地私有目录，不包含在公开附件中。
