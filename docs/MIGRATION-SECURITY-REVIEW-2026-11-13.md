# 迁移后安全与客户端补漏审查

本轮基线为 `1792ade`，检查当前运行入口对应的 Go 后端、Web、PC、Android、iOS 和独立后台。工作区开始时干净。保留原有界面样式、旧 PHP 源码及数据库，不改写已执行的数据库迁移。

## 发现并修复

| 范围 | 问题与影响 | 修复 |
| --- | --- | --- |
| Go 依赖 | 漏洞扫描识别出 PostgreSQL 驱动和 WebP 解码相关可达调用链。可达不等于已经证明线上可利用；WebP 风险涉及异常内存分配 | pgx 升至 5.9.2，x/image 升至 0.45.0，x/crypto 升至 0.59.0，edwards25519 升至 1.1.1，并更新必要传递依赖；复扫无已知漏洞 |
| PC 依赖 | 原锁文件 npm 审计为 19 项：1 critical、13 high、5 moderate | Electron 43.8.10、electron-builder 26.18.0；固定 minimatch 11.0.1，复扫 0 项。开发 Node 要求至少 22.12.0 |
| 管理后台 | 切换登录后旧请求仍能返回并填充缓存；多步骤保存可能在读取后改用新会话的 CSRF/入口继续执行 | 整次请求冻结会话代次、CSRF 与入口；传输和转换后再次校验。头像、上传、导出使用同一边界；图片上传在散列前检查类型大小限制 |
| 联系人 | 列表缺少备注和个人分组，名称缓存可能把已迁移备注覆盖为空 | 完整列表、分页列表和精简资料都按当前查看者关联元数据；双向不同备注及第三人隔离回归通过 |
| 私聊 | 会话头像读取会话表，而私聊实际使用对方用户头像，导致四端私聊头像缺失 | 在现有查询中选择对方头像；没有新增按会话查询用户的循环 |
| 群成员 | 列表把账号当昵称，Web/PC/iOS 没有补头像授权 | 返回实际昵称及查看者备注，在当前受限成员集合内补头像；保留只显示管理者等原权限 |
| Android | 被拉黑或已不可见的可选头像返回 403/404，导致联系人/成员/会话整页失败 | 仅对可选头像的 403/404 回退默认头像；401、会话变化及其他错误仍抛出。聊天附件继续使用严格授权 |
| PC 媒体 | Go 的图片、音频、视频均使用不带扩展名的授权链接；缓存把所有 Go 链接认作图片，拒绝音视频 MIME | 在本地显示链接传递严格枚举的媒体类型，缓存依照类型检查 MIME；保留账号、会话、消息边界及 Range 校验 |
| PC 更新 | 原生更新入口默认未配置，且不识别 Go 的 latest_version/latest | 默认请求配置的 Go /client/update，带 pc 平台和当前版本；保留显式配置的独立更新清单 |
| PC 打包 | 生产构建仍强制读取旧 PHP 的线路签名模板；配置真实 Go 地址也被拦住 | 使用已验证的 Go HTTPS API 作为线路发现信任起点；移除 PHP 模板依赖，继续校验 HTTPS/WSS 同服务与 /api/v2 路径 |

Go 扫描初次记录为 GO-2026-4771、4772、5004、5932、6222、4503，其中 5004 和 6222 识别到调用链。这里只记录扫描证据，不声称已经针对生产账号复现漏洞。部署包应使用新二进制；仅更新源码无法修复正在运行的旧依赖。

- 独占本机测试库运行 `scripts/verify-core.ps1`：133 个具名测试事件通过、0 跳过；`go vet`、Windows 构建、Linux/amd64 交叉构建通过。图像、ffprobe、真实音视频样本参与测试。
- `govulncheck v1.9.0 ./...`：依赖升级后无已知漏洞。默认下载源曾超时，随后通过模块镜像取得工具，模块校验保持启用，漏洞数据库仍为 vuln.go.dev。
- `npm --prefix pc audit --registry=https://registry.npmjs.org --json`：0 项。原 npm 镜像不提供审计接口，未把其 404 当成通过。
- Node 27 项回归通过，覆盖后台迟到响应、跨会话写入、群成员头像、PC 音视频缓存与 Range、更新协议、生产打包配置和之前的客户端回归。
- 真实本机 Go/PostgreSQL/Redis 的共用 Web/PC 适配器：116 次请求通过，包含新增备注目录断言及原有隐私、群历史、CAS、消息、原图摘要、缩略图等检查。预期拒绝按相应错误码判断。
- Android：APK 和测试 APK 离线构建通过；Android 12 模拟器 23 组检查通过，包括新增可选头像拒绝/401 不被吞掉、目录备注，以及实际音视频上传、备用线路通知、任务工资等原场景。
- iOS：54 个 Swift 文件语法解析，Foundation 适配器和模型编译，16 组真实本机 Go 场景通过，包含联系人目录元数据断言。

- `npm --prefix pc run check`、共享源码同步、五端路由清单和 iOS 工程静态校验通过。静态盘点为 Web 62、PC 71、Android 82、iOS 77、后台 68 个路径片段，不是逐界面功能验收计数。

## 验收边界

没有 Mac，仍不能用本轮 Linux Swift 检查替代 Xcode App target、iPhone、Apple CryptoKit 上传或 iOS WebSocket 生命周期验收。Windows 本轮未配置 CGO 编译器，因此未重新执行 race；普通测试与 race 证据不混算。

本轮没有重新进行万人在线、300 图或全部旧 PHP 业务逐项等价验收。APNs/FCM/Telegram 外部到达和未提供的第三方生产凭据不由接口测试代替。本轮也没有增加手机端原图选择界面或改变既有相册每批选择限制；服务端原图保留及浏览器原图上传已有验证，不能据此声称手机发送原图选项已经完成。

正式同步结果以本报告后续部署记录为准。Android、iOS、PC 源码修复需要重新构建客户端，不能自动更新已安装版本。
