# Go 后端单机容量压测（2026-11-11）

对象为 `verification-09/pulse-im.exe`。应用、隔离 PostgreSQL 和 Redis 被限定在同四个逻辑 CPU；三个 Windows Job 的内存硬上限合计 7.5 GiB。主机本身是 24 逻辑核、约 32 GiB 内存，并共享其他工作负载；本次不是生产或 Linux 实机测试。

| 指标 | 结果 |
| --- | ---: |
| 在线连接 | 10,000 / 10,000，意外断开 0 |
| 60 秒聊天发送 | 6,000 成功，P95 10.3 ms，P99 38.6 ms |
| 单账号图片突发 | 300/300 处理完成；300 条图片消息成功 |
| 图片期间聊天 | 1,835 成功，P95 41.2 ms |
| 上传限流 | 451 次 429，按原请求号重试后全部完成；503 为 0 |
| 三进程族峰值提交内存之和 | 1.09 GiB |
| 应用峰值堆已分配 / 堆系统内存 | 436 / 740 MiB |

每张测试 JPEG 为 3,681,911 字节、2048×1536 像素；约每五张选择原图，其余走普通处理。错误路径返回符合预期：坏序号 400、无效会话 401、伪造媒体 403、空正文 400。429 为有界拥塞拒绝，客户端按原请求号重试；300 张最终均 ready 并形成 300 条消息。结束后连接数归零，媒体、消息 outbox、发送和推送队列无积压，PostgreSQL 和 Redis 保持就绪。

同一版本普通测试及 race 各 94 个具名事件，无跳过；`go vet ./...`、Windows 构建、Linux/amd64 交叉构建均通过。原始证据位于 `D:/IM/.local/backend-full/verification-09` 和 `D:/IM/.local/backend-full/load-10000-09`；后者包含结果、两秒间隔样本、进程族限制记录和服务日志。

限制：旧 MySQL 数据尚未实际导入；APNs、FCM、Telegram 使用模拟端点回归，未验收真实设备；Linux 实机、长期 soak 和四端完整功能联调尚未执行。容量结果不能证明旧 PHP 的全部业务已等价迁移。
