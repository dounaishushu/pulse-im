# 手机发送图片本地预览

## 视频与原因

用户描述的文件实际位于 `C:\Users\Administrator\Desktop\IM问题处理\fxc.mp4`（56.79 秒）。录屏中选图返回聊天后，图片先缺失，随后出现空白加载区域，实际图片在上传、消息确认及下载后才显示。

Android 正常发送图片时，先前为隐藏左下角文件名与发送状态文字，隐藏了整个待发图片行；本地入队前又要等待会话权限复核、图片准备，因此空白等待更明显。此外，上传返回的 `pulse-media:<id>` 不是可下载的 HTTP 地址，旧的本地上传缓存写入被跳过，确认消息后还需下载自己的图片。iOS 同样缺少上传期间的聊天图片行。

## 修改

- Android 选图结果返回时创建右侧本地图片预览，解码缩略图不等待权限复核、压缩或网络上传。实际发送继续执行原有权限检查。
- 使用两个后台线程与有容量上限的内存缓存解码图片，处理照片方向；正常发送期间不恢复左下角文件名、排队文字和移除提示。图片角落保留小型发送指示。
- 上传阶段变化沿用同一个预览视图；多图选择与入队使用一致的请求编号，按选择顺序发送。失败保留图片及重试、移除操作，重试复用请求编号。
- 恢复待发队列时，从原有加密附件读取缩略图，读取结束删除临时解密文件；账号与会话仍分别隔离。
- 确认消息接替本地预览时，先写入显示缓存，再移除待发行，避免图片重新闪空或重复出现。上传文件缓存使用当前会话绑定的真实媒体授权地址，通常可复用上传响应中的授权，无需额外请求。
- iOS 在私聊与群聊列表增加待发图片行，从相册资源、选择器对象或准备完成的本地文件获取缩略图；服务器确认后复用本地缩略图。保留原有照片处理、顺序发送及失败恢复流程。

预览只表示本地已选图片；其他人收到图片仍取决于上传及服务端确认。网络或服务端较慢时，发件人的本地图片仍可提前显示。

## 验证

Android 使用独立测试包名 `com.pulseim.android.scrollprobe` 和本机不可达地址 `127.0.0.1:9`，未连接生产会话或覆盖原安装应用。

- `OutgoingPhotoProbe`：私聊、群聊共 **26 项通过**。人为阻塞权限复核、图片处理及上传，验证两张图片已经实际绘制到屏幕，检查选图顺序、阶段更新保留视图、加密队列恢复、失败重试与移除、账号隔离、确认接替及重复确认。使用不可达图片地址，验证本地上传图片缓存仍能读取原有尺寸。
- `ChatRefreshProbe`：**12 项通过**，复核既有会话刷新与生命周期行为。
- `ChatFirstPaintProbe`：**10 项通过**，复核私聊、群聊首屏逐步显示。
- JavaScript 单元回归：**98 项通过**；浏览器公共代码同步检查通过。
- Android Gradle 编译通过；交付 APK 另做包名、版本、后端地址、签名及 ZIP 对齐检查。
- iOS 三个修改文件语法树检查无错误；工程静态引用检查通过（55 个 Swift 源码引用、136 个工程对象）。Windows 环境未进行 Xcode 编译或 iPhone 真机验收，交付为源码包。
