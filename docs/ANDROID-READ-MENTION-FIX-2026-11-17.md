# Android 已读与 @ 提醒修复

对应 **Android 0.2.99 (101)**，2026-11-17。

## 原因与修改

原有本地已读覆盖只处理 `unread_count`，没有处理 `unread_mention_count` 和 `last_mention_message_id`。已读请求成功后，会移除待发送记录，而旧聊天列表仍保留此前的计数；完整本地目录回调也未应用已读覆盖。因此返回保留的聊天列表或接收迟到的旧目录时，“有人@你”及未读数可能再次出现。

现在阅读已显示的消息后，立即更新保留列表中的未读和 @ 提醒，并按阅读边界更新磁盘目录。成功回执保留已确认的阅读位置、服务端计数及状态版本，用于处理保留列表、分页、完整目录和底部导航计数中的旧数据。消息多于阅读边界时继续保留未读；旧 @ 已阅读但后来有普通新消息时，仅清除旧 @。账号、会话凭据或接口切换后清理本地确认状态。

Go 适配器传回已读回执的状态版本。仅当回执中仍有手动“标为未读”的标记时，使用现有接口清除该标记；正常阅读不增加这次请求，送达回执不清除标记。较新版本重新设置的未读提醒继续生效。全部使用现有 Go 接口，无需服务端迁移。

## 验证

独立包名 `com.pulseim.android.scrollprobe`、不可达默认地址与进程内 API 夹具下运行：

- `ConversationReadProbe` **22 项通过**。覆盖待发及确认后的已读、返回保留列表、迟到旧数据、后续普通消息与 @、部分阅读、重试、请求合并、账号和接口隔离、手动未读、送达回执、实际适配器、加密目录及真实列表控件。阅读前后截图显示“有人@你”和未读数字一并清除，新 @ 仍重新显示提醒。
- `ChatDeltaProbe` **19 项回归通过**。增量切换保留消息、草稿和未变化的节点，打开请求延迟 2.3 秒时仍有旧内容，重复返回群聊仅首次读取完整历史，后续使用增量游标。
- Android 主包和测试包编译、`git diff --check` 通过。测试使用本机受控数据，没有向生产群发消息。
