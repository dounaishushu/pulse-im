# 手机上翻消息位置修复与验收

版本：Android 0.2.102（104）；iOS 1.0（build 82，源码）。适用于群聊和私聊。

## 现象与原因

阅读历史消息时，新消息会把画面拉回底部。此前客户端只在手势发生时取消当前滚动任务；普通消息、迟到的发送回执或后台同步随后又重新发起跟随，覆盖了阅读历史的意图。Android 全量恢复还把“存在新消息”直接视为“原本在底部”。

Android 的滚动触摸监听也可能被可点击的消息内容绕过；回到底部按钮则占用了单一滚动监听槽位，覆盖了向上分页的监听。

## 行为

- 上翻时持续暂停自动跟随，新消息在底部追加，保留当前阅读位置。
- 连续来消息、后台增量或历史补齐、迟到的发送回执，以及下方图片尺寸变化，都不能重新开启跟随。
- 自己明确发送文字、图片或附件时恢复跟随；发送过程中再次上翻，后续回执继续尊重新的阅读位置。
- 点击回到底部或手动滑到底部后恢复跟随。在底部收消息仍自动展示最新消息，布局及键盘尺寸变化继续保持底部。
- Android 在消息子视图分发触摸前取消旧滚动任务；使用手势位置版本，防止已排队的历史位置恢复覆盖后续拖动。回到底部按钮改用独立滚动观察，不覆盖原来的历史分页监听。
- iOS 的实时消息与同步消息共用持续阅读暂停状态，旧的滚动任务不能绕过暂停；群聊和私聊增加回到最新消息按钮。保留显式定位消息、账号及访问权限边界。

## 验证

Android 隔离模拟器共 76 项检查通过：

- `ChatReaderProbe` 24 项：实际 MainActivity 群聊与私聊，检查初始显示、底部来消息、上翻后连续来消息、迟到的自己消息 ACK、下方消息高度增长、真实回到底部按钮、真实发送按钮和本地队列、大量新消息时不裁掉正在阅读的记录、取消已排队滚动、手动回到底部。
- `ChatScrollProbe` 32 项：群聊与私聊的滚动控制，包括图片延迟高度、输入区改变视口、行替换、手势取消任务、旧导航和非活动账号隔离；确认浮动按钮不会覆盖历史分页监听。
- `ChatDeltaProbe` 20 项：实际 API 适配与增量渲染，包含连续拖动期间新消息响应与排队锚点恢复的竞争；原会话缓存、草稿、单次全历史读取、编辑撤回、个人删除清空和权限拒绝回归通过。

测试包为 `com.pulseim.android.scrollprobe`，使用模拟器、回环测试地址及受控数据；发送检查只进入隔离本地队列。中途有一轮检查因测试包切换被打断，已按顺序单独重跑并取得上述通过结果。

iOS 更新 Foundation 滚动状态测试用例；ChatView、ChatScrollState 和测试源码语法树无错误，现有工程、plist、scheme 与发布配置静态检查通过。当前 Windows 没有 Swift 编译器或 Xcode，未执行 Swift 测试、SwiftUI 语义编译或 iPhone 实机验收，也没有 IPA。

iPhone 需在原 Mac/Xcode 签名环境构建后验证：群聊、私聊上翻时连续接收消息和补同步；图片延迟显示及键盘变化；发送过程中再上翻；点击回到底部、手动滑到底部；定位引用消息和切换账号。

Android 沿用调试签名验收包及现有生产 HTTPS/WSS 地址，安装新版后生效。交付目录保存检查日志、源码指纹、包名/版本/地址/签名/完整性核对和 SHA-256；iOS 提供 build 82 源码 ZIP。
