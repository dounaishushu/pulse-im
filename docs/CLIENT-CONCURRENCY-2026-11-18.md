# 客户端发送与消息同步解耦

日期：2026 年 11 月 18 日。验证版本：PC 2.4.189、Android 0.2.107（versionCode 109）。在作者的 `615d063` 基线上合入本次修复。

## 改动

- Android 原先要求文字和附件同时恢复，且恢复任务排在聊天归档后面。现在两个队列分开恢复，发文字只需要在后台保存文字。保存期间界面可操作；若失败，输入仍在，迟到的结果也不会清掉随后输入的文字。
- Android 的待发状态认领、回执保存、重试和草稿读写均在后台执行。保留已加密的本地数据、同一会话的发送顺序、稳定的请求 ID 与账号隔离。
- Android 界面读取存储版本时曾与 SQLite 读写共用一把锁，长事务会把界面一并拖住。将轻量的版本检查与实际读写分离，提交前仍检查任务是否过期。旧缓存被权限或消息版本检查拒绝时，只检查一次已知的较新版本，避免递归重绘崩溃。
- PC 与 Web 沿用作者独立的侧栏刷新和轻量目录探测，再把已读回执从当前会话的增量读取中拆出。侧栏或回执延迟时，当前会话仍可追平；编辑、撤回和私删继续按服务端权限重读必要窗口。
- Android 停顿报告保留至多三次主线程状态和栈采样。PC 记录超过 200 ms 的慢帧，含可取得的脚本、布局和绘制耗时，仍只写本机日志。两端均不在新增字段中记录聊天正文或凭据。

## 现场证据

11 月 18 日北京时间 10:28:24—10:46:16 的代理样本中，477 次发消息请求均返回 `201`，P95 为 27 ms。11:49:47 读到服务健康、重启次数为 0，服务端消息队列和数据库锁等待均为 0。这表明已经到达服务器的发送在该窗口内大多很快；它不能衡量发请求前的本地等待或接收端绘制时间。

同日上午安卓 0.2.106 上报 60 次前台实时断连，涉及 21 个账号。两条主线程停顿报告为 7.68 秒和 9.936 秒。9.936 秒那条抓栈为 `ViewRootImpl.relayoutWindow → BLASTBufferQueue.nativeDestroy`，另一条落在系统帧回调；单次栈只说明采样时线程在哪里。需要同一设备的多个样本及复现动作确定这些现场停顿的触发源；没有证据把它们全部归因于本地队列或服务器。11 月 17 日的 PC 2.4.176 日志曾记录约 46.6 秒无响应，但没有当时的调用栈。

## 回归结果

- Node 检查 187 项。PC 与 Web 两个实际页面共 16 项恢复检查，其中侧栏与回执同时挂起、增量接口返回一次 503 后，仍能自动显示新消息。另有 86 项阅读滚动、12 项轻量目录检查；保留作者的批量绘制验证。PC 安装包构建通过；从同一包的程序目录实际启动，3125 个打包源文件与工作区一致，合成慢帧写入一条 449 ms 的本地诊断。
- Android API 31 模拟器 126 项：阅读及本地待发 30 项、附件 26 项、增量同步 23 项、切换会话 35 项、渲染 12 项。注入读写延迟时，界面可继续输入，迟到的草稿不会覆盖新输入；文字保存不等待附件和聊天归档恢复。触发受控停顿验证多次栈成功记录。使用独立包和受控服务，未完成现场手机或 Windows 覆盖安装测试。
- 现场系统渲染停顿和部分实时连接断开仍需另行确认。本次回归覆盖已定位到的客户端等待关系，不能证明所有现场卡顿已消失。
