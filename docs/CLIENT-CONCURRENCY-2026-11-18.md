# 客户端发送与消息同步解耦

日期：2026 年 11 月 18 日。验证版本：PC 2.4.189、Android 0.2.107（versionCode 109）。在作者的 `615d063` 基线上合入本次修复。

## 改动

- Android 原先要求文字和附件同时恢复，且恢复任务排在聊天归档后面。现在两个队列分开恢复，发文字只需要在后台保存文字。保存期间界面可操作；若失败，输入仍在，迟到的结果也不会清掉随后输入的文字。
- Android 的待发状态认领、回执保存、重试和草稿读写均在后台执行。保留已加密的本地数据、同一会话的发送顺序、稳定的请求 ID 与账号隔离。
- PC 与 Web 沿用作者独立的侧栏刷新和轻量目录探测，再把已读回执从当前会话的增量读取中拆出。侧栏或回执延迟时，当前会话仍可追平；编辑、撤回和私删继续按服务端权限重读必要窗口。

## 回归结果

- Node 检查 152 项。PC 与 Web 两个实际页面共 16 项专项检查，其中侧栏与回执同时挂起、增量接口返回一次 503 后，仍能自动显示新消息。另有 86 项阅读滚动检查。
- Android API 31 模拟器 111 项：阅读及本地待发 28 项、附件 26 项、增量同步 22 项、切换会话 35 项。注入读写延迟时，界面可继续输入，迟到的草稿不会覆盖新输入；文字保存不等待附件和聊天归档恢复。使用独立包和受控服务，未完成现场手机或 Windows 覆盖安装测试。
- 现场系统渲染停顿和部分实时连接断开仍需另行确认。本次回归覆盖已定位到的客户端等待关系，不能证明所有现场卡顿已消失。

这批没有 Go、管理员后台或数据库改动。Android 为测试签名包，未配置正式签名和 Firebase；Windows 未配置代码签名。证书不同时安卓无法覆盖安装；不要卸载现用包来验证，卸载可能清掉设备本地待发消息和草稿。
