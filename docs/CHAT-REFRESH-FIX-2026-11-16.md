# 聊天自动清空、重新加载与闪烁修复

日期：2026 年 11 月 16 日。源码基线：`ad4fa62b30b16cf76ac8651392ed1a365734cdee`。

用户反馈手机聊天使用一段时间后自动刷新、长时间转圈，PC 出现短暂闪烁。本轮找到并修复会主动清空已加载消息的客户端路径；没有取得截图设备的实时日志，因此不把所有网络长尾都归因于同一个触发源。

## 确认的问题与修改

### PC / Web：个人变更通知直接清空整个会话

`personal.changed` 不仅代表清空全部记录，还覆盖未读提醒及单条个人删除。原处理收到通知即清空消息、重设历史加载状态，随后重新打开会话。延迟返回时会出现空白或权限校验占位。

修复为在原消息容器中执行受授权的快照对账：保留未变化的消息和阅读位置，只移除确认删除的行。收到重连 ready 通知时同样保留当前页面。实际 401/403/404、成员版本变化等原有失效路径继续生效。

在修改前，新增浏览器断言复现失败：个人提示到达后，原消息节点已经断开且历史代次改变。修改后将同步响应挂起，确认等待期间仍保留节点和原阅读位置；返回后单条删除正确移除目标消息。

### Android：普通暂停与个人提示触发聊天重建

原 `onPause` 除了应用自己的选图页以外，会清空整个 Go 聊天并将历史设为未加载；恢复时重新构建页面。个人变更提示也直接执行相同失效处理。

已加载的同一会话暂停时，现在保留消息视图、历史状态和草稿，暂停旧的恢复结果，并要求恢复后重新获取访问和发言权限，再恢复发送及历史补齐。暂时无法连接时保留原聊天，不将网络失败转换成历史失效。个人提示取消较旧的在途快照，再在原页面补齐变化。

确实尚未加载、身份已失效、实际访问拒绝或成员版本变化时，继续走原有清理和重新授权流程。选图回调仍须通过恢复权限检查。

### iOS：普通群提示与场景暂停清空记录

原视图将群成员/个人提示视为已确认的权限失效，直接丢弃历史；场景短暂 inactive 也清空已加载消息。

提示现在只刷新群资料，并交由既有的受授权历史对账判断成员版本、清空边界和删除结果。同一登录及端点下的短暂场景暂停保留消息，返回后执行对账。账号/端点失效仍清理；权限查询返回实际访问拒绝时及时丢弃原历史。

本轮 iOS 仅完成源码、工程及语法检查，没有进行 Xcode 构建或手机真机验收。

## 验证与交付

- 92 项 Node 客户端测试通过；PC/Web 语法及共享 JS 副本一致性检查通过。
- PC 和 Web 的私聊、群聊四组实际页面共 58 项检查通过，覆盖延迟个人变更、重连、单条删除、原节点与位置保持，以及模拟服务返回 403 后清理。
- PC 群主、管理员、普通群员三组页面检查通过，成员版本变化与访问拒绝仍触发原有保护。
- Android 在独立应用 ID、仅限本机不可用 API 的模拟器探针中完成 12 项检查：两类会话的暂停保留、草稿保留、等待权限、网络不可用恢复、个人提示及实际失效方法清理。未覆盖用户已安装应用，未使用真实账号发送消息。
- Android 离线编译通过。iOS 工程引用检查通过；SwiftUI/UIKit 运行行为仍需 Apple 环境验收。
