## 审查发现

### 尚未通过的阻断项

- **P1：功能覆盖不足。** 注册/验证码/资料/安全与手机绑定，媒体上传与私有下载，收藏/频道/文件夹/会话设置，搜索/@/引用/置顶，内部资料/抖动/群发，后台与角色、任务题库工资、分发、清理、推送、Telegram 等均未闭环。当前不能切换旧前端或旧数据。
- **已处理：用户已确认临时聊天及邀请时选择历史。** 当前非好友按接收方隐私联系，拉黑拒绝；邀请显式提交 allow_history，重新入群版本递增。群邀请具备所有人/联系人/无人及例外，不强制好友。旧端联调仍待完成。
- **P2：历史回执迁移不能从水位猜测事实。** 当前版本已用 004 迁移后的排除区间修复清空/个人删除后再读的误计数；早期 Go 版本已经制造的旧回执无法从水位反推。旧 PHP 导入必须使用真实回执；退出成员累计阅读统计也需按旧库继续验收。
- **P1：离线目录与旧端缓存恢复尚未联调。** 后端目录、access、群详情、sync 已提供历史起点及成员版本，sync 可拒绝旧成员版本；客户端仍需在重连/重入群时核对、清除不可见缓存并重建。关系/成员变化目前仍依赖 outbox 提示和完整目录重新核对。
- **P1：数据迁移与兼容尚缺。** 旧 PHP 消息多类型/业务 ID/密码及凭据/媒体授权/任务工资/权限设置没有导入器与核对脚本；Go 的 `migrate` 仅创建新表，不迁移旧业务数据。旧前端 token、HTTP/WS、消息 DTO 均未联调。
- **P1：容量尚无验收。** 当前逐会话补齐、逐消息回执聚合及 outbox 收件人查询存在大群读放大；未在整栈 4 核/8—16 GiB 下验证 1 万在线、重连洪峰、积压恢复和慢客户端。
- **P2：批量邀请异常会丢失部分成功报告。** 逐目标已提交后若遇数据库错误，HTTP 返回通用错误而不返回已完成项；需要稳定操作键与可恢复结果。
- **P2：通知/审计/维护不全。** 好友申请与拒绝没有完整实时/离线通知；成功登录未存 IP/设备类型、没有失败日志。事件、登录会话与审计无保留期清理；就绪检查不反映 worker 积压。
