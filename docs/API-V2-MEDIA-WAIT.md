# 媒体上传的短时等待与就绪授权

2026-11-15。适用于 Go v2、PC 2.4.158 及同源 Web 适配层。

媒体仍按“创建上传任务、传输字节、后台处理、提交消息”的流程工作。客户端可以在以下请求中附加 `wait_ms=1500`：

```text
PUT /api/v2/media/{id}/bytes?wait_ms=1500
GET /api/v2/media/{id}?wait_ms=1500
```

`wait_ms` 必须是 0～1500 的整数，同一请求只能出现一次。未指定或为 0 时保留原有异步响应。传输成功的 PUT 仍返回 HTTP 202，GET 返回 HTTP 200，响应中的 `status` 是真实媒体状态，不能把 HTTP 202 当作媒体已处理完成。

当后台处理在等待窗口内完成时，响应直接包含 `status: "ready"`、真实尺寸/MIME/字节数等原有媒体字段，以及可选 `access`：

```json
{
  "id": "媒体 UUID",
  "status": "ready",
  "mime": "image/jpeg",
  "bytes": "98266",
  "width": 932,
  "height": 975,
  "access": {
    "token": "临时不透明授权",
    "expires_in": 120,
    "content_path": "/api/v2/media-grants/<64hex>/content",
    "preview_path": "/api/v2/media-grants/<64hex>/preview"
  }
}
```

客户端可将 `access` 放入当前登录会话的媒体授权缓存，直接用于提交消息后的显示。授权不进入数据库中的消息内容、日志或公开验收记录。缓存随账号/会话变更清空；内容服务仍重新检查会话和消息可见性，原始 `/media/{id}/grants` 接口继续可用。

仍在排队或处理中时，服务器返回真实的 `queued` / `processing` 状态，客户端继续请求状态。服务器最多保留 64 个短时等待者；等待槽已满时立即退回原异步状态。工作进程保留 250ms 恢复扫描，新任务额外发送内存唤醒信号；处理仍使用既有的两个工作进程和像素内存预算。HTTP 请求不直接解码文件。

客户端首次使用创建任务返回的状态，减少一次重复 GET。传输结果不确定后重试时，仍先查询原任务，不重新创建附件。PUT 返回就绪结果时跳过额外状态请求，并复用随回执返回的授权；旧服务器忽略 `wait_ms` 时仍可通过原状态接口完成上传。较慢任务的继续等待支持取消，处理阶段按实际耗时限制为 90 秒。

共享 PC/Web 适配层还合并当前窗口、聊天列表和实时同步的并发授权请求。某一窗口离开只取消该消费者的等待，其他消费者继续取得授权；账号切换会使旧请求结果失效。

针对正常配置来源，CORS 预检响应增加 600 秒缓存。来源白名单、校验和、文件格式校验、媒体权限、幂等请求编号及消息发送顺序均继续执行。
