# Go 后端与四端功能、安全复查

范围：`D:\IM`、`codex/go-rewrite`，基线 `0d64cbb`。保留上轮未提交的后台、禁言、搜索、历史、媒体缓存及手机原图改动，本轮继续审查默认 Go 程序、固定 PHP 源码、Web/PC 共用适配器、Android、iOS 和独立后台。没有暂存、提交、推送、部署，也没有写正式 PostgreSQL、MySQL 或旧媒体。

结论：四端的既有请求都有 Go 适配或明确的历史分支分类；本轮实际发现并修复了消息隐私和作者展示的遗漏。**路径盘点不是全部功能验收；162 项保留需求仍不能判为完整等价。** 上轮原图接线与容量边界见 [手机原图补漏](MOBILE-MEDIA-GAPS-2026-11-14.md)。

## 已复现并修复

| 级别 | 问题 | 改动与验证 |
| --- | --- | --- |
| P1 | 旧 PHP `GroupInviteNoticeService` 将“邀请某人入群”系统记录限于当前群主、管理员；Go 导入后按普通系统消息暴露 | 在独立测试库复现历史、全局/会话搜索、摘要、未读、事件同步、单条读取和引用回复泄露。增加持久 `manager_only` 边界，覆盖这些入口以及回执、个人删除、撤回、置顶、媒体可见性和推送；普通系统消息继续可见。已验证内部员工身份不能代替群内管理员角色，降级后拒绝旧历史快照，撤回后保留受限边界 |
| P2 | Go 成功邀请缺少旧版保留的群内管理记录 | 在邀请的同一事务写入系统记录、消息序号、事件和 outbox；只恢复管理者隐藏的会话。重复邀请不重复生成，不更改原有历史授权；频道不新增此类群管理记录。模拟 APNs 接收器验证只向符合条件的管理员推送 |
| P1 | 任免管理员、转让群主和后台换群主没有同步推进成员版本，迟到历史可能继续按旧权限缓存 | 对实际角色改变递增 `membership_version`，原有四端成员版本校验继续生效。任免后的旧快照返回 409；服务器按当前角色重新判定可见性 |
| P2 | 可见消息未携带作者展示身份；受限群无法靠完整成员列表补昵称，引用经常只显示“会话成员” | 在受权限保护的消息投影返回作者昵称及头像 ID，覆盖发送、重放、编辑、历史、搜索、摘要、同步、单条和引用父消息。三套适配器同时补 Web/PC、Android、iOS 显示字段与受权头像。验证作者退出后历史仍有作者身份，但其他成员仍不能取得受限资料、完整名册、手机号或账号私密字段 |

新增迁移仅为 `060_manager_notice_visibility.sql`。它添加受众标记并识别已导入记录，包括正文已清空但归档仍能识别的撤回记录；不改原正文和归档。迁移器也为以后导入的旧邀请记录写入此标记。临时表执行实际迁移 SQL 的测试覆盖正常记录、现存邀请、已撤回归档。先前 `001`–`056` 没有改写；本轮与此前未发布的 `057`–`059` 一并保留。

## 运行验证

- 本机独立 `pulse_parity_review_20261114_test`、Redis DB 12：`go test ./... -json -count=1` 与 `go test -race ./... -json -count=1` 均有 **152 个具名通过事件、0 具名跳过**，两次用例集合一致。真实 ffprobe、WAV、MP4 参与。`go vet ./...`、Windows 构建、Linux/amd64 交叉构建通过，208 个源文件哈希与测试清单一致。

- Node 契约、PC 媒体/更新/独立历史窗口及后台检查：**36 项通过**。`npm run check` 通过。后台、Web、PC 和共享源的改动保持原界面样式。
- Android 离线调试 APK、instrumentation APK 构建通过；Android 12 模拟器使用实际 App API 层：**26 组场景通过**，包括新增作者字段、权限、媒体原图校验、批量队列与真实音视频。清空测试改为对照服务端实际序号边界，避免把对成员不可见的管理记录误认为序号不存在。
