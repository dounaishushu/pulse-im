# Android 群聊增量同步

## 上一版仍空白的原因

用户在 Android 0.2.97 的基础上反馈：切换群聊后仍有两三秒空白。上一版虽然先创建聊天框，但 `conversation.changed` 普通消息提示和 `personal.changed` 提示仍会删除会话快照，已进入过的活跃群很容易丢失本地显示数据；两分钟期限、暂停和实时连接变化也会丢弃快照。返回时仍等待完整历史请求。

本次没有继续只隐藏加载标识，而是接入服务端现有的 `/conversations/{id}/sync` 与 `/personal-sync` 接口，不需要增加或部署服务端接口。

## 现在的流程

1. 首次取得会话的授权历史时，记录消息事件与个人事件两个游标。初始游标取自历史请求之前的会话列表摘要，避免用较晚的 `/open` 响应或可见消息的最大事件号跳过并发消息。
2. 已有记录的会话再次进入，先显示当前账号内存中的记录和已有图片；不再请求最近一页完整历史。权限在后台重新确认，发送权限不取自记录快照。
3. 使用消息事件游标拉取新增、编辑、撤回，使用个人事件游标拉取个人删除、清空等变化。两条流分别分页，固定各自快照上限，逐页检查进度、范围、会话和成员版本。
4. 在原列表合并变化，保留未变化的消息节点、草稿和阅读位置；新增消息继续按原规则到达最新位置。个人删除和清空先过滤，防止同批旧事件重新插入；撤回与编辑仍执行版本检查，并更新引用。
5. 普通消息和个人变更提示只安排补同步，不丢弃已有记录。暂停、重连或超过两分钟不清除当前登录会话的已有记录；切换账号、退出登录、已知成员版本变化和真实访问拒绝继续执行隔离与清理。

记录缓存仍有数量和大小上限（8 个会话、每个最近 20 条），只存在于当前活动实例内存。首次访问、进程重启、缓存淘汰或真实权限范围重置时仍可能需要初始历史请求；这不等同于能让尚未取得的数据脱离网络立即显示。缓存只显示既有内容，不缓存发送授权。

## 验证

`ChatDeltaProbe` 使用独立测试包名 `com.pulseim.android.scrollprobe`、本机不可达默认地址和进程内 API 响应，在真实 `MainActivity → ApiClient → GoV2Api` 路径完成 **19 项检查**：

- 收到普通消息提示后，离开的群仍保留记录；人为阻塞打开接口 **2.3 秒**，已有内容一直可见，草稿可编辑，实际发送保持受限。
- 多次返回同一群、接收实时新消息与个人变更时，完整历史总共只读取 **首次的 1 次**；后续请求使用已保存的事件游标和个人游标。
- 新增、编辑、撤回、个人删除和清空正确合并，未变化的视图和草稿保留；新消息到达后仍滚动到最新位置。
- 覆盖消息与个人事件分页、固定快照、空的过滤页推进、无进度页拒绝、中途取消、成员版本不匹配及 403 拒绝后的清理。

另运行切换检查 **35 项**（按保留本地记录、重新验证发送权限的新规则更新断线与期限断言）、首屏 **10 项**、刷新 **12 项**、发图 **26 项**及消息滚动探针。日志、请求路径及阻塞期间截图随安装包保存在 `verification`。以上是受控本地功能验证，没有使用生产账号、向真实群发消息或进行线上高并发性能测量。
