# PC 与 Go 后端接口兼容修复

2026-11-19。PC 源码版本 2.4.193，用户 Web 2.4.196，数据库迁移仍为 063。

## 群成员列表错误

此前交付的 PC 2.4.192 在普通群员身份下按旧规则推导目录权限：浏览群主和管理员，搜索本群好友。新版 Go 在群组未禁止互加好友时返回完整成员目录。旧客户端收到 `members_visibility=all`、`search_scope=group` 后，其严格校验会抛出 `invalid_response`，即使服务端 HTTP 返回 200。

`GET /api/v2/groups/{id}/member-profiles` 现在保留无版本参数时的旧目录契约。新客户端显式携带 `directory_version=2` 获取由群开关控制的完整目录；未知版本返回 400。旧目录在数据库查询时限制角色/好友范围，分页游标、查询回显和权限元数据同步，不能在取出一页后仅过滤显示。

Browser 共享适配器、PC、Android 和 iOS 源码均已传递目录版本；仅同步浏览器 Go 适配器，没有运行会覆盖其他 PC 模块的全量同步脚本。群成员 ID 接口也使用同一个事务内的群开关和角色规则，修复 ID 列表与资料列表不一致。

保留原规则：开启禁止互加好友时，普通群员只浏览管理者、只搜索本群好友；管理者继续查看完整目录。目录可见性不会授予管理、邀请、禁言或加好友的额外写权限，写操作仍重新校验当前状态。

## 从群聊打开好友资料显示“未公开”

内部员工从群聊打开已有好友时，客户端会带上群上下文。资料接口原先要求该员工同时是该群管理者，导致本可在好友列表查看的相同资料返回 403。

资料接口保留内部员工身份检查和有效群成员检查；群内普通角色的内部员工仅在与目标确有好友关系时保留原有资料读取能力。非好友继续受原群角色限制；普通账号、已退群账号和已解除好友关系的请求继续拒绝。没有修改用户账号权限，也没有开放普通用户读取登录/IP 资料。

## 验证与交付

- 使用实际交付 PC 2.4.192 的应用源码复现新目录响应被拒收，再验证旧契约恢复以及新适配器的版本协商，共 3 项。
- 207 项客户端单元检查通过；22 项生产目录 SQL 的隔离 PostgreSQL（PGlite）检查通过。
- 使用独立合成 PostgreSQL 数据库和独立 Redis 实例运行实际 Go HTTP 回归，覆盖旧/新目录契约、开关、分页与搜索、资料授权和拒绝、成员 ID、作者及头像元数据。没有用生产业务库运行测试。
- 两项附带头像测试最初因测试容器的 1 GiB tmpfs 触发媒体最小可用空间保护而返回 507；改用独立临时磁盘目录后复核。这不表示生产磁盘不足。
- 后端部署保留数据库备份、旧镜像、旧版本目录、完整性清单和原静态哈希资源。没有新增迁移，不清空消息、好友和本地数据。
- PC 2.4.193 需要新的安装包才能获得完整目录显示。旧 PC 在后端兼容层恢复原目录行为，无需等待新包才能消除本次目录错误。
- 本轮不交付 Android APK 或 iOS IPA；对应源码已同步请求版本，iOS 完整构建仍需 Mac/Xcode。
