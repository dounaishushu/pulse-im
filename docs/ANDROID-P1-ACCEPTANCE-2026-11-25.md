## 本轮变更

- 增加纯 JVM `ChatFrameStats`：读取 gfxinfo 的应用汇总；严格检查 p99 < 16ms、卡顿率 < 1%，按原始帧计数计算卡顿率。
- 排除窗口重复统计、GPU分位数和legacy卡顿数；缺失、截断、多进程混合、溢出和无效样本按失败处理。
- `ChatRecyclerProbe` 保留10秒、200条消息滚动与原有功能检查，增加结构化性能结果；性能不达标时返回失败，而非仅记录采集完成。

## 性能结论和适用范围

环境为API 37模拟器、1080×2400、60Hz、宿主NVIDIA GeForce RTX 5060 Ti。使用隔离应用ID与关闭的本机端点，没有登录生产账号或访问生产API。

异常轮次的Perfetto显示：`waitForBufferRelease`最大24.70ms，`layout`最大1.27ms。**由此推断图形呈现和缓冲等待是主要限制，仍需真机确认**，不能由这份模拟器结果推断线上手机表现。

本轮修改前，在宿主GPU模式下的首轮基线已经是15ms；这些数值不代表本轮代码带来的性能优化收益，也不能将最好的13ms单独用于判定P1完成。三轮中一轮失败，稳定性能验收仍未完成。

追踪分析使用[Perfetto官方Trace Processor](https://perfetto.dev/docs/analysis/trace-processor)，没有调整显示分辨率、刷新率或验收门槛以获得通过。

## 后续修复：多选局部刷新（同日）

原代码在多选模式中每次选中/取消单条消息，都会向全部消息发送选择刷新。在修改产品代码之前，新增设备回归稳定复现了 `Single deselection notified 205 rows`。

新增纯 Kotlin `ChatSelectionUpdates` 保存选择状态快照。进入/退出多选更新全部消息以调整宽度；模式不变时只更新勾选状态变化的消息，重复状态不发通知。按消息 ID 定位当前索引，排除加载头与待发行；延迟刷新会丢弃过时请求，继续保留阅读锚点。

修复后群聊、私聊均验证单次选择/取消只通知 1 行，重复选择状态通知 0 行，保留行实例及阅读位置。新增 12 项 JVM 测试，总计 69 项通过；新旧路径构建通过，旧路径 4 项回归通过，群聊/私聊初始截图哈希与上述基准完全相同。

## 后续修复：复用行的发送者名称（同日）

新增设备回归在修改产品代码前复现了 `Reused sender label is stale: 群成员`：消息昵称字段已更新，原行仍显示旧名称。复用绑定只更新了消息正文与时间，没有重新绑定群聊发送者标签。

仅在新列表绑定中计算当前发送者标签，沿用当前账号的名字解析规则。昵称变化时更新显示及备用昵称；本机备注继续优先，清除备注后恢复最新昵称。相同身份、备用昵称和显示值时跳过标签写入；消息与内容 View 保持同一实例，阅读锚点保持不变。
