# 旧 MySQL 数据迁移验收

2026-11-12 已把一致快照恢复到独立 MySQL 13306，再直接导入服务器本机的独立 PostgreSQL `pulse_legacy_rehearsal`。旧 PHP、原 MySQL 3306 和原媒体目录继续运行且未删除。当前服务端支持旧 PHP 的 bcrypt 密码哈希校验、16 位公开 ID 读取，并以 `pulse.legacy_ids` 保存旧数字主键与新 UUID 的双向映射。

025 前向迁移增加逐消息 `pulse.receipt_facts` 和 `imported_legacy` 标记。旧库已读进度只是游标，不能据此生成旧消息的回执；导入器已复制真实的 `message_receipts` 行，保留 `delivered`/`read` 状态。Go 新登录后的已读／送达操作使用独立覆盖水位，从该操作时才生效。隔离测试覆盖旧水位很高但回执稀疏的情况。

026 前向迁移把消息请求号列扩至 80 字符，与旧 PHP 表宽度一致；新客户端仍按 64 字符规则生成请求号。导入器须原样保存旧请求号，不得裁剪。

`server/cmd/legacy-audit` 为只读盘点工具，要求显式设置 `PULSE_LEGACY_MYSQL_DSN` 和 `PULSE_POSTGRES_DSN`，只接受旧库 `pulse_im`、隔离目标库 `pulse_core_test`，输出唯一新报告。它只记录表名、预期字段、行数和目标映射，不输出账号、消息正文、密码、设备令牌或连接串；`can_run_import=false` 是刻意的阻断位。已于 2026-11-11 只读核对旧服务器与数据库结构，不将凭据写入报告。

正式导入必须停旧写入或建立可重放的增量边界，在同一旧库快照下导出；先备份并保留原库和媒体目录，再导入隔离 PostgreSQL，逐表核对数量与样本哈希。导入时固定映射用户、会话、消息、媒体、任务、题目、作业与后台账号；成员范围、清空水位、个人删除、已读/送达事实、撤回、群邀请历史、头像和附件文件必须一起对账。不得用当前读水位推造旧回执，不能把不存在的旧附件当作已成功发送。历史中的钱包、红包路由在固定 PHP 版本里已明确返回“不可用”，应保留原库历史备份，不作为活跃重写功能重新启用。

切换前还须验收：旧账号登录及二步密码、原公开 ID/二维码、好友与黑名单、群成员和重入历史、跨类型消息及附件、个人清空/删除/回执、任务题目快照及工资；最终数据必须来自冻结旧写入后的新快照或可重放增量。不一致则停止切换并保留旧服务。
