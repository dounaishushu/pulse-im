# PC 上翻消息位置修复与验收

对应 PC **2.4.180 / Windows x64**，2026-11-17。覆盖群聊和私聊。

## 原因

实时追加消息时，`appendMessage` 无条件要求回到底部；Go 后台同步收到比当前更新的消息后，也无条件把恢复位置标为底部。原有滚动控制只取消当次跟随，后续通知和回执能重新启动跟随，因此阅读历史会被新消息打断。

## 调整

- 增加持续阅读暂停状态；上翻后，新消息继续追加，保留当前可见消息及其偏移。
- 实时追加、后台同步、文字/图片待发状态和发送回执共同遵守阅读状态；图片延迟显示、窗口调整和临时布局收缩不能重新开启跟随。
- 支持滚轮上翻、拖动滚动条、PageUp/Home 等键盘导航。窗口、账号、会话和定位消息继续使用原来的权限与导航边界。
- 自己明确发送或重试、点击回到底部，或手动向下滑到底部后恢复跟随。在底部收到新消息继续自动显示最新内容；发送过程中再次上翻，迟到的回执尊重后续阅读位置。
- 回到底部需要等待网络时，若期间发生了新的阅读手势，完成后的回调不能再覆盖阅读位置。
- 共享 Go 同步适配增加可选的滚动许可检查，并保持 PC、Web 与共享副本一致。Web 原有行为保留，通过兼容回归验证。

## 验证

- 实际完整 PC 页面夹具：私聊 28 项、群聊 29 项，共 **57 项**。覆盖连续同步消息、实时追加、自己的消息入队后立即显示、ACK 迟到、读取期间滚动、历史分页锚点、鼠标滚动条、键盘、手动回到底部、非活动账号键盘隔离、窗口及图片高度变化、临时布局收缩、@ 插入和访问拒绝。
- Web 私聊 14 项、群聊 15 项，共 **29 项**兼容回归；四种页面场景共 86 项通过。
- 客户端单元测试 **146 项**、PC JavaScript 语法和 `git diff --check` 通过。
- 群资料按群主、管理员、普通成员三种角色回归，禁言标识 20 项检查通过。
- 页面验证使用本机受控 API、消息及发送队列，没有向生产好友或群发送测试消息。
