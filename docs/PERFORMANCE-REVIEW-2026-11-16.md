每组现有/候选查询均返回 8 行。上表仅是 SQL **执行**时间，现有规划时间约 13.9—15.2 ms、候选约 10.3—11.1 ms，均未包含在上表耗时内；这不是端到端提速倍数，也不能替代权限回归。实验按现有再候选顺序执行，有缓存预热影响；索引循环和缓存块访问量的下降提供了额外证据。

验收：普通附件、头像、群头像、作业、128 个混合媒体、重复 ID、拉黑、冻结、退群、撤回、清历史和并发撤权；比较完整结果集合及 HTTP 状态。保留每次会话/权限校验，只改变查找路径。

### P1：后端停止给旧客户端返回明知无法显示的头像

位置：`server/internal/core/messages.go:20`、`server/internal/core/reply_context.go:45`、`server/internal/core/client_queries.go:106`。

消息作者、引用作者和私聊对象会返回头像 ID，但头像授权规则要求对应用户 `active`。在另一份最后 50000 行样本中，109 个被拒绝的媒体里：

- **108 个**是已停用用户的头像，没有消息附件引用，贡献 **8591 次被拒请求**。
- 另外 1 个属于有效账号，贡献 200 次；尚未定位该类请求的具体查看者，不能推断都是同一原因。

建议在消息/引用/会话摘要中，对停用账号及已知不可展示的头像返回空头像或明确的可用状态，让现有默认头像接管。头像文件和历史消息仍保留，媒体授权保持现有规则。校验旧客户端空头像行为后，服务器单独发布即可减少这类无效请求。

验收：账号停用/恢复、历史作者显示、引用消息、私聊列表、拉黑关系；用户重新启用或换头像后可刷新恢复。不能通过放开媒体权限来消除 403。

### P1：会话列表减少历史未读与引用上下文的重复计算

位置：`server/internal/core/client_queries.go:106`、`:158`、`:184`；`server/internal/core/client_pages.go:22`。

每次列表查询都重新计算每个会话的未读，再查询最后消息和 @ 提醒，分页入口还另查总数。未读兼容旧 PHP 的逐条 `receipt_facts`；`LIMIT 1000` 限制的是最终匹配数，不保证只检查 1000 条历史记录。线上已有约 681.8 万条旧回执事实，实际观察到大量回执索引访问。

建议分两步：先用代表性用户验证 SQL 计划、将不变的摘要复用到同一请求中；再引入按会话事件版本、成员版本和个人状态版本失效的摘要缓存或增量统计。客户端只刷新有变化的会话，引用上下文按消息版本与可见性版本复用。单纯缓存固定时间或用 `message_seq-read_seq` 相减会破坏旧回执、撤回、个人删除、加入边界和管理员消息规则。

验收：普通/旧消息混合、未读和 @、个人清空/删除、管理员降级、退群再入群、新消息与已读并发；缓存失效后的结果与原始查询逐项一致。

### P2：后台 worker 空闲时退避，心跳合并落库

位置：`server/internal/core/delivery_jobs.go:379`、`server/internal/core/media.go:546`、`server/internal/core/observability.go:14`。

群发队列每 200 ms 探测；两个媒体 worker 每 250 ms 探测。`ObserveWorker` 每轮执行结束都更新 `worker_heartbeats`，没有任务也落库。本次 14.26 秒内产生 **141 次心跳行更新**，约 9.9 次/秒；媒体实际处理轮数为 0。

建议使用提交后唤醒加空闲渐进退避，仍保留定期兜底扫描以恢复进程重启/跨实例任务。普通成功心跳每 10—15 秒合并落库，错误、恢复与重要状态变化立即落库，累计运行计数不能丢失。这里的 10—15 秒是候选配置，尚未实施。

验收：空队列 SQL/写入量、任务提交后启动延迟、定时任务准确性、进程重启接管、心跳健康判定。不要仅拉长轮询而使发图或群发响应变慢。

### P2：管理员首页合并重复统计请求

位置：`admin/src/views/DashboardView.vue:42`、`admin/src/go-api.js:263`、`:269`、`:357`。

本地加载真实适配器、模拟网络复现：首页 4 个逻辑数据请求产生 **7 次 HTTP 调用**，其中 `/admin/stats` 和 `/admin/health` 各调用 2 次。统计适配器还等待健康响应后才返回统计卡片数据。

建议由首页共享一次 stats 和一次 health 结果，地区统计复用用户总数。完整首页理论调用数可从 **7 降至 5**，减少 2 次/约 29%，不代表整个后台减少 29%。共享范围限定同次加载/同一登录身份，保留取消和权限变更处理。

验收：初次加载和手动刷新网络计数、部分接口失败时其他卡片可用、快速切页/退出登录不会填入旧结果。

### P2：管理员媒体缓存加并发合并、容量上限和正确释放

位置：`admin/src/go-api.js:130`、`:153`；`admin/src/features/messages/MessageContent.vue:24`。

`mediaBlob` 仅缓存完成结果。同一媒体并发调用两次，都会下载并创建 Blob URL，后完成者覆盖 Map 中的引用。本地已复现：**2 次下载、2 个 URL，reset 只释放 1 个**。此外 Map 在会话内没有数量/字节上限，查看大量视频或附件会继续保留内存。

建议按管理员登录身份和媒体 ID 合并在途请求，对完成缓存做按字节的 LRU；视图引用释放后再淘汰，下载型附件用完即释放。共享任务不能因一个视图取消而错误中止其他消费者。

验收：相同媒体并发、快速切换详情、取消后重开、退出账号、连续查看大附件；核对下载次数、创建与释放数量、内存上限及最终播放器行为。

### P2：管理员带哈希静态资源可长期缓存

位置：`server/deploy/nginx/pulse-go.conf` 的管理员静态目录规则。

通过线上 TLS 对 5 个实际带哈希 JS 文件发起 HEAD，全部返回 **`Cache-Control: no-store`**，其中一个文件未压缩大小 220922 字节。gzip 已开启，本项要解决的是重复访问缓存。

建议只对正式构建 `/assets/` 下带内容哈希的公开 JS/CSS/字体设置长期 immutable 缓存，精确校验文件存在；HTML、专属入口和私有 API/媒体分别保留相应的刷新/授权策略。无需客户端重新打包，需更新服务器静态配置并检查新增 location 的安全响应头。

验收：首次/二次加载实际传输字节、发布新哈希能更新、旧 HTML 不长期滞留、404 不返回 SPA HTML、专属入口与私有内容不进入公共缓存。

### P3：后台下拉搜索仅保留当前结果与已选项

位置：`admin/src/components/EntitySelect.vue:47`。

每次远程搜索把旧 `rows` 和新结果合并，没有淘汰。多次搜索后，候选数会随历史关键词累计，旧结果也可能继续出现在远程候选中。

建议当前搜索结果替换旧结果；仅额外保留已选项和必要的初始回显，配合已有 250 ms 防抖与取消逻辑。

验收：连续搜索不同关键词、清空搜索、多选与回显、关闭重开；候选条数有界，已选值不丢失。本项当前为代码证据，未做浏览器实测。

## 3. 客户端后续项：本轮仅记录

- 成功媒体授权已有短期缓存和在途合并，**403/404 失败没有短期抑制**。对 Git HEAD 源码做离线复现，同一媒体连续调用 20 次：成功只联网 1 次，403 会联网 20 次。建议对确定的不可用结果短期退避，角色/账号/头像变化时清理；401 处理登录状态，429 遵守退避，不能统统当图片不存在。
- 共享适配器 `hydrateMessages` 在返回消息前等待引用上下文和媒体授权；PC 的部分会话变更又触发历史恢复与列表刷新。建议先呈现文字与已有缓存，再补可见区域媒体，合并同一会话的更新，按游标取增量；重连缺口、权限变化仍走完整恢复。
- 样本 A 中内容下载 906 次、缩略图 33 次、内容 304 仅 2 次。应继续检查各端缩略图选择、稳定缓存标识和视图复用；这些计数不能单独计算缓存命中率，也不能证明所有内容下载都属于不必要的原图。
- Nginx 未记录客户端版本/UA，当前日志无法判断请求来自哪一版 PC/Android/iOS，也不能把全部重复请求归因于作者的新版本。没有进行本轮真机测试。

## 4. 网络传输与观测补充

部分图片响应的 Nginx 总耗时达到数秒。另一个样本中，约 246 KB 的一次下载总耗时 68.351 秒，上游耗时 8.351 秒，表明单看 Go SQL 无法解释全部端到端等待；也有约 12 秒总耗时与上游耗时几乎相同的响应，仍需区分传输背压、连接和应用等待。

当前普通 API/媒体与 WebSocket 都配置了 `proxy_buffering off`。可以单独评估下载缓冲及鉴权后由 Nginx 发送文件的方案，先验证 Range、304、账号退出/撤权和慢客户端场景；不能据此直接断定关闭缓冲就是慢图根因，也不应一并改动上传和 WebSocket。

数据库尚未启用 `pg_stat_statements`，`track_io_timing` 关闭；本轮使用现有累计计数和有界活跃查询采样，没有开启全量 SQL 日志或修改数据库参数。后续可补路由级耗时、数据库连接等待、队列最老年龄、客户端版本计数，先核算采样开销；不要记录令牌、图片授权路径或消息正文。
