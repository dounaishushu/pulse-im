## 当前实现自身的审查与修正

- 分页若过滤所有事件仍推进原始扫描游标，避免死循环。
- outbox 不保存正文；客户端读取早期事件也投影当前撤回状态。
- 租约 token 参与完成条件，旧 worker 不能删除新 worker 的租约任务。
- 原子计费有界发送队列；关闭时清空计费，旧连接退出只清理自己。
- WS 登记完成后 ready 屏障，之后再取目录和补齐，避免握手与快照漏通知。
- session/hash 校验后再次锁用户检查密码是否变化，防止校验期间重置后创建旧密码会话。
- Redis 失败保留有限读恢复和退出能力，一般写与新登录明确 503。
- 同批会话变化合并，避免按每个事件重复查询接收者及广播。
- 按 F037 收紧回执隐私：其他成员不获得个人水位或阅读人身份，发送者仅查询自己可见消息的聚合人数。
- 默认 module graph 仅包含当前代码；旧路由不通过 side-effect import 意外启用。

## 仍需处理的不足

1. 当前只有文字消息闭环，166 项尚未全部实现；完整资料、联系人备注和账号安全流程不能由现有关系/群 API 代替。
2. 拉黑、删好友、退群、禁言和群停用已有写接口与并发回归；更细的隐私例外、群审核和旧前端联调仍待完成。
3. 变化提示+正文拉取在大群下会增加读取请求，需客户端合并、服务端批量/授权后缓存和真实负载评估；当前不承诺 4 核万人高频群播。
4. 单会话 capped 未读及个人删除/清空持久事件已实现；批量列表未读、历史 retention/resync、附件私有授权、任务/工资、后台和 Telegram 仍待完成。
5. 容量压测、旧数据迁移、旧前端联调、Linux 实机和容器运行尚未验收。
6. 旧参考源码依然含上述问题；只隔离路由不是把所有旧源码都修好，后续移植时必须按审查项补齐，禁止整体重新启用。
