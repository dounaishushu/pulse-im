# Android 会话切换优化

## 录屏与原因

查看 `C:\Users\Administrator\Desktop\IM问题处理\加载.mp4`（41.42 秒，Android 录屏）。两个已看过的群来回切换时，仍先显示只有标题的加载页，随后重建聊天界面，再显示消息。图片内容也在消息显示之后补齐。

此前首屏优化让授权消息先于图片、引用补齐返回，但 Android 进入会话仍受 `/open` 请求阻塞。每次先创建 `ChatOpeningView`，待会话信息返回后才创建消息列表与输入框；Go 模式为避免把磁盘历史当作授权依据，不在进入时直接恢复磁盘记录。因此，已经看过的会话再次进入也重复等待。

此外，首屏结束后会启动自动历史归档，循环向前翻页；干净首屏还会立即安排补同步。这些请求可能与当前页面共用网络和服务端资源。录屏没有服务端请求耗时、数据库等待或线上负载数据，不能据此量化服务端瓶颈。

## 本次修改

- 从会话列表点击时，使用列表中的会话摘要立即创建完整聊天框与输入区，不再先经过独立加载页。输入草稿可编辑，实际发送仍等待新鲜的会话授权。
- 增加仅限内存的近期会话快照：最多 8 个会话、每个最近 20 条消息、最长 2 分钟。只有同一账号、登录会话、服务端和仍认证的实时连接可复用，并核对已知成员版本、清空边界；不从磁盘恢复 Go 会话作为授权依据。已有图片缓存可直接显示。
- 后台 `/open` 与历史请求继续并行。历史响应通过现有权限和成员版本校验后，可先显示，不必再等待较慢的 `/open`。会话授权、群人数、私聊状态及发送权限在原聊天框更新，保留草稿和未变化的消息视图。
- 新鲜历史替换快照中已删除、已编辑的消息，并清理确认不可见的引用。新消息、成员权限和个人历史提示使对应快照失效；读状态、回执提示不清空消息快照。断线重连、暂停、切换账号或服务端会使快照失效。真实拒绝访问继续关闭会话并清理缓存。
- 普通打开过程不显示中央转圈；真实失败仍显示可点击的重试提示。首次进入、缓存失效或断线时，聊天框可先出现，未取得的服务端消息仍需等待真实网络响应。
- 切换会话先取消旧的后台归档传输，Go 每次打开最多自动预取一页更早历史；继续保留手动翻页、已读历史存储和断点信息。修正旧归档任务结束时清理新任务状态的竞态。
- 实时连接正常、首屏期间没有收到内容变更提示时，首屏本身完成当前消息窗口同步，避免立即重复补读。期间有新提示、重连或连接不可用时，继续执行补同步。

## 验收与版本

使用独立包名 `com.pulseim.android.scrollprobe` 和本机不可达接口 `127.0.0.1:9`，不使用生产账号，不发送真实消息，也不覆盖原应用。

`ChatSwitchProbe` 在两个前台 HTTP 工作线程均被阻塞时，走真实 `openExistingChat → showChat → loadHistory` 路径，验证私聊、群聊的即时聊天框、可编辑草稿、短时快照与缓存图片；随后分别放行会话授权、历史预览、完整历史，检查原界面更新、删除与编辑对齐、干净首屏不重复补同步、期间有新提示时保留补同步。另检查快速切换旧请求取消、临时断网保留草稿、403 清理、账号与连接隔离、过期与清空边界、成员版本变化、内存数量限制，以及旧归档传输取消。
