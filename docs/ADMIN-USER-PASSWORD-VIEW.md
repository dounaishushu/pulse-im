# 后台查看用户密码

编辑用户中增加「用户密码 → 查看密码」。仅超级管理员可用，每次查看须输入当前后台账号的密码。成功后显示 30 秒；手动隐藏、切换用户、关闭编辑窗口、退出登录、界面接收到超级管理员权限变更、页面隐藏或窗口失焦都会清空显示。普通管理员仍可按原有权限重置密码。

含换行或控制字符的密码使用带引号的 JSON 转义形式显示，避免单行输入框悄悄删掉字符。「复制原始密码」从接口返回的原始字符串复制，不从显示框读取。复制仅在点击按钮时执行。

## 启用

1. 部署本次后端与 admin 前端，先执行 `pulse-im migrate`，应用迁移 `067_user_password_copies.sql`。
2. 生成一次独立的随机 32 字节密钥，Base64 编码后写入服务器私有环境配置的 `PULSE_USER_PASSWORD_ENCRYPTION_KEY`。例如可在服务器执行 `openssl rand -base64 32` 生成，然后通过私有配置渠道保存。密钥不得提交到 Git 或放进可下载的安装包、前端文件、日志与普通数据库备份。
3. 所有 API 实例和创建用户的 CLI 使用同一密钥，配置完成后重启。生产 compose 从 `/etc/pulse/pulse.env` 读取；本地 compose 已支持传入该变量。未配置时功能关闭，原有登录、注册与改密仍正常运行；配置格式无效时服务启动失败。
4. 从启用后创建或重新设置的用户密码可查看。已存在的 Argon2/bcrypt 哈希不能还原；后台会显示「尚无可查看的密码记录」。旧用户仅登录不会补录密码。

## 保存和权限

登录仍使用原有密码哈希。额外的可查看副本使用 AES-256-GCM 加密，存于独立的 `pulse.user_password_copies` 表，只保留当前密码。每条记录使用随机 nonce，并以用户 ID 和当前密码校验值作为认证附加数据，防止调换到其他用户或旧版本密码。

注册、CLI 创建、后台单个/批量创建、后台单个/批量重置以及用户自行改密，均在更新哈希的同一事务内保存新副本。数据库触发器在密码哈希变化或软删除时清除旧副本，覆盖功能关闭和其他 SQL 写入路径。硬删除使用外键级联清除。批量重置重试不会覆盖用户之后自行修改的密码。

`GET /api/v2/admin/users/{id}/password-status` 仅返回是否可查看。`POST /api/v2/admin/users/{id}/password-reveal` 需后台会话、专属入口、CSRF、HTTPS（或本机调试）、当前数据库中有效的超级管理员角色和管理员密码。每个管理员每分钟最多尝试 10 次，密码校验沿用全局并发上限。返回禁止缓存。用户列表、资料、导出和普通 IM 接口不包含密码副本。

成功查看和管理员密码验证失败会写入审计日志，包含操作者、目标用户、来源 IP、请求 ID 和结果，不记录任何密码。成功查看必须先提交审计事务，审计失败时不返回密码。

## 密钥维护

加密副本意味着服务器持有密钥时能够还原密码，这是本功能增加的访问能力。私有密钥与数据库应分开保管，独立限制读取权限。不要复用后台账号密码或其他业务密钥。

更换密钥不会自动重新加密已有副本；旧密钥对应的记录会显示不可读取，需恢复原密钥或重新设置该用户密码。关闭功能后修改密码会清除旧副本；再次打开不会恢复该记录。应保留受控的密钥恢复方案，并让所有写入实例使用一致配置。
