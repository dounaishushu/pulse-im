# PC 已读与 @ 提醒修复

对应 **PC 2.4.177 / Windows x64**，2026-11-17。Android 已在 **0.2.99 (101)** 处理，本轮 Android 源码未变。

## 原因与修改

PC 的 Go 兼容层覆盖了通用已读入口，直接发送回执并只记录已读序号，没有同步修改当前列表的 @ 与未读计数。通用已读处理也依赖回执中可选的 @ 字段，而 Go 适配器只返回普通未读计数；其旧响应保护仅覆盖“回执确认前已发起”的查询。

现在 Go 的实际入口保留原有可见消息、焦点和会话检查，并使用统一的已读状态处理：

- 阅读请求发出时，立即清除已显示范围内的未读数和旧 @ 提醒，更新列表而不替换消息节点。切换会话期间收到的成功回执仍可更新对应列表行。
- 回执传回服务端状态版本，按版本和阅读边界合并完整列表、增量列表及当前会话，阻止旧响应恢复提示；64 位状态版本使用精确比较。
- 阅读边界以后的新消息、新 @ 继续提醒；旧 @ 已读而后续只有普通新消息时，仅清除旧 @。较新手动“标为未读”继续显示，打开阅读后用现有接口清除标记。正常阅读不增加清除标记的请求，送达回执不清除该标记。
- 保留已有的回执合并、前台重试及账号隔离；仅清除已有阅读证据覆盖的范围。

共用 Go 适配器按现有目录规则同步到 PC/Web 源码。无需修改或部署 Go 服务。
